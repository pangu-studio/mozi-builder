## 边界

- 平台不进入业务请求与已发布任务的必经链路：平台 API 宕机不影响已发布服务与已调度任务（架构红线），HA 目标是**控制面**的恢复能力，不是数据面。
- 双库备份恢复以 PostgreSQL 标准工具（pg_dump/base backup + WAL）为准，不自研。

## 工作分解

### 1. HA（控制面）

- 平台 API 多副本：无状态 handler + SKIP LOCKED 认领（阶段 4）+ 租约恢复已天然支持；需要补的是**启动时的恢复健康检查**（双库 verify 之外加 `/healthz` 就绪探针，供 Compose restart policy / 外部 LB 使用）。
- Controller（发布操作、任务派发）多副本安全：发布操作有唯一活动索引（0003），任务派发幂等（execution_id）——补一个多副本竞争集成测试证明。
- 会话：Bearer 摘要存库，多副本共享，无需 sticky session（阶段 1 已满足）。

### 2. 审计检索

统一查询 API（成员读，跨项目拒绝）：

| 端点 | 数据源 |
|---|---|
| `GET /projects/:id/audit?action=&actor=&from=&to=&cursor=` | 平台库 audit_events |
| `GET /projects/:id/design-changes?kind=models|services|jobs&cursor=` | 设计库 *_history 三表归一 |
| `GET /projects/:id/executions?job=&state=&cursor=` | 平台库 job_executions |

- 统一游标分页（created_at + id 复合游标，替代当前 500/100 硬上限的逐步替换；既有接口保持兼容）。
- 保留策略：超期数据归档导出（JSONL）后删除；归档产物经 OSS/本地卷，保留期随目标值定。

### 3. 观测

- 结构化日志：go-zero 请求日志当前关闭（避免凭证泄露——阶段 1 决策保留）；新增**领域事件日志**（发布操作转移、任务触发/失联、晋级/回退），JSON 行格式，不含凭证。
- 指标（`/metrics`，Prometheus 文本格式，仅内网）：发布操作状态计数、任务 attempt 结果计数、回读失败率、Drifted 资源数、审计写入失败数。
- 告警阈值随目标值定；本阶段只暴露指标。

### 4. 凭证轮换

| 凭证 | 轮换流程 |
|---|---|
| JWT 签名密钥 | 双密钥窗口：新密钥签发 + 旧密钥仅验签，窗口期后下线旧密钥 |
| fire_key（Dkron/执行器共享密钥） | 双密钥窗口同 JWT；轮换后重跑 Dkron SyncJob |
| APISIX Admin key / Dkron | 配置注入更新 + 验收栈重跑冒烟 |
| 数据库账号 | 迁移账号与运行账号分权（阶段 1 遗留项，本阶段落地）+ 轮换演练 |

每次轮换在 progress.md 记录证据（日期、窗口期、验证方式）。

### 5. 恢复演练（每类一次实测，证据入 progress.md）

1. **数据库恢复**：从备份恢复到新库 → 双库 verify → API 启动核验。
2. **控制面全量重建**：丢弃全部容器与卷 → 从配置 + 数据库重建 → 发布操作继续（租约恢复）。
3. **凭证泄露应急**：轮换 fire_key → 旧密钥立即失效（403 实测）→ 任务链路恢复。
